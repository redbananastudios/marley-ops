## 1. Phase A — Crew Reliability (all built)

### A1 — Job sheets delivered outside the app
A night-before, per-crew **day-sheet PDF emailed** + **login-less SMS link**, re-sent when a job changes.

- **New server-side PDF capability** (the app previously rendered PDFs only in the browser via CDN pdfmake):
  - `lib/pdf/server-pdf.ts` — pdfmake Node printer → PDF buffer/base64.
  - `lib/pdf/fonts-data.ts` — base64-embedded TTFs (generated by `scripts/build-pdf-fonts.mjs` from `public/fonts/vfs_fonts.js`); embedded (not fs-read) so they survive Next standalone tracing.
  - `lib/pdf/pdfmake-node.d.ts` — minimal ambient types.
  - `next.config.ts` — `serverExternalPackages: ["pdfmake"]` so pdfkit/fontkit trace in untouched.
  - Dependency added: `pdfmake` (verified rendering from the built standalone bundle).
- **Data + rendering**: `lib/crew-sheet/daily-data.ts` (`assembleDaySheets` — reuses `assembleJobSheetData` so paper/web/in-app can't drift; survey photos threaded via `surveyId`), `lib/crew-sheet/daily-docdef.ts` (price-free multi-job doc-def, photos embedded).
- **Dispatch engine**: `lib/crew-sheet/dispatch.ts` + cron `app/api/cron/crew-job-sheets/route.ts` (every 5 min). Sends at 19:30 UK the evening before (was 18:00; Peter, 2026-07-30); content-hash change detection → superseding re-send within a tick; transient-failure retry with a cap + terminal `failed`; single-flight claims (upsert-ignore create, content-hash CAS change, attempts-CAS retry); a no-contact crew is surfaced once and not re-tried.
- **Login-less web copy**: `app/sheet/[token]/page.tsx` — noindex, reads **live** data, "last updated HH:MM", PII-stale after 3 days. Same token pattern as `/q`, `/s`, `/cv`.
- **Office visibility**: `lib/crew-sheet/delivery-log.ts` + a failure panel on `app/(dashboard)/automations/page.tsx`.
- **Migration**: `supabase/migrations/0068_crew_job_sheets.sql` — `crew_job_sheets` (state per staff+date: version, content_hash, delivered_hash, attempts, token) + `crew_job_sheet_sends` (append-only log). Office-read RLS, service-role writes.
- **Registry**: `lib/cron/jobs.ts` — added `crew-job-sheets`, **removed `crew-reminders`**.
- **Retired**: `app/api/cron/crew-reminders/route.ts` **deleted** (the day sheet subsumes its "you're on N jobs tomorrow" email; running both double-emailed crew).

### A2 — PWA read caching (offline shell, "designed on purpose")
The service worker was push-only by deliberate design; this adds a tightly-scoped read cache.

- `public/sw.js` — **network-first** for `/my-jobs*` documents (offline falls back to last good copy; a signed-out redirect is never cached), **cache-first** for immutable `/_next/static/*`, offline fallback (`public/offline.html`), versioned + FIFO-trimmed caches, `activate` cleanup, a `mm-clear-cache` message handler.
- `lib/pwa/cache-rules.ts` — pure predicates/constants, **mirrored into `sw.js`** and pinned by `tests/lib/pwa/cache-rules.test.ts` (same discipline as `lib/push/payload.ts`).
- Crew UI: honest **"Updated HH:MM"** stamp (`components/pwa/last-updated.tsx`, server-baked time), today+tomorrow **prefetch** (`components/pwa/jobs-prefetch.tsx`), the persistent offline indicator (now folded into the A3 sync bar).
- Sign-out wipes the crew cache (`components/my-jobs/sign-out-button.tsx`).
- **Note:** `MAX_STATIC` was raised to 400 (a code-review fix) so FIFO can't evict a chunk a cached `/my-jobs` doc still needs.

### A3 — Offline write queue
Crew actions taken with no signal are persisted on-device and replayed on reconnect.

- `lib/offline/outbox.ts` — pure, unit-tested flush core: oldest-first, removes an item only on confirmed `done`, retries transient failures to a cap then flips to `failed` (**never dropped**), treats a thrown runner as retry; `enqueue` collapses to one pending item per `(kind, key)`.
- `lib/offline/db.ts` — dependency-free **IndexedDB** store (chosen over the Background Sync API because **iOS Safari doesn't support it** — the crew's phones; we flush in-page instead).
- `components/offline/outbox-provider.tsx` — flush lifecycle (on reconnect / foreground / every 30s / after enqueue), single-flight lock, `router.refresh()` when something syncs.
- `components/offline/runners.ts` — maps `job_completion` → `completeJobAction`.
- `components/offline/offline-sync-bar.tsx` — unified bottom bar (offline / "N will sync" / "Syncing…" / "N couldn't sync — tap to retry") + `PendingSyncBadge`. **Supersedes** the A2 `offline-banner.tsx` (deleted).
- Wired: `components/crew/complete-job-button.tsx` — online = immediate; offline OR a dropped mid-submit = queued (cert built on-device); **fails loudly** if IndexedDB can't store it. The Complete button becomes a "Saved — waiting to sync" badge so a queued job can't be re-signed.
- Mounted in `app/my-jobs/layout.tsx` (the crew shell).
- **Exactly-once** = single-flight flush + idempotent server actions (completion is unique on `appointment_id`).

### A4 — Idempotency & versioning
Mostly an audit — prior hardening already covered the named paths; verified and fixed the one real gap.

- **Verified idempotent (no change):** completion (`job_completions.appointment_id` unique → `alreadyCompleted`), card settle (atomic status claim), card refund (atomic reserve), deposit/balance/storage invoices (slot-claim `NULL→'pending'` + adopt-by-reference).
- **Fixed the real gap:** `app/actions/job-media.ts` `recordJobMediaAction` now upserts with **ignore-duplicates on `storage_path`** (its natural key). Previously a dropped-response retry hit the unique index and surfaced a permanent "Could not save"; a partial-batch retry lost the new item. Client toast handles the count-0 case ("Already filed"). Tested in `tests/lib/job-media-idempotency.test.ts`.
- **Version + SW auto-update:** already present — `BrandMark` shows `v <sha>`; `UpdateBanner` + `PushSwRegister` update installed PWAs within one launch; A2's caching never pins the app shell.

### Phase A code-reviews
Two `/code-review` passes ran on Phase A; all findings fixed (retry-claim CAS, photo-reuse across crew-mates, SW cache-eviction cap, empty-day `is_active`, no-contact short-circuit; the SMS-any-channel behaviour was documented as intentional because the email carries the same link).

## 8. Gotchas & open decisions

- **Money format**: customer-email prose renders whole amounts as **£1,700** (the app's `gbp()` strips `.00`); the PRD says `£1,800.00`. Deliberate, already-tested house style — left unchanged. **Confirm or change.**
- **SMS vs email delivery**: a sheet is marked delivered when *any* channel succeeds — an email-OK/SMS-failed crew member isn't stranded (the email carries the same login-less link + the PDF) and the failed SMS is surfaced. Documented as intentional in `dispatch.ts`; don't "fix" it into re-sending (that would re-email).
- **Crew phone numbers**: SMS only fires where `staff.phone` is set; blanks log `skipped`. Populate before go-live.
- **Migration numbering**: use **0069** next.
- **Prod already has** the estimator/security session's `0067` applied (per project notes); this branch's `0068` is the only unapplied migration.
