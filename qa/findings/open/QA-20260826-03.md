## Summary
`/clients` throws React error #418 (hydration mismatch) in the browser console on every load. The page renders correctly, but a hydration mismatch forces a client re-render of the tree and can mask genuine bugs behind the constant console noise.

## Repro
1. Role: office (staging, commit bf678a9 — but pre-existing, not gate-12 work; neither gate-4 nor gate-12 diffs touch a date-rendering path here).
2. Open `/clients` with the browser console visible.
3. Expected: no console errors.
4. Actual: minified React error #418 (text-content mismatch between server and client render) on every load, both List and Grid modes.

## Evidence
Observed live by the gate-12 role-QA agent (2026-08-26) on every `/clients` visit during its run, alongside otherwise-passing assertions. Likely cause: a relative-date or locale-formatted string computed at render time (server timezone/locale vs browser) — the usual #418 shape in this codebase's list pages.

## Suggested angle (for the repair tier)
Un-minify locally (`npm run dev`, open /clients) to get the exact mismatching text node, then anchor the offending timestamp/relative-date through a deterministic formatter or a `suppressHydrationWarning` ONLY if the value is genuinely client-local by design.
