## Summary
`e2e/crew/job-completion-status-consistency.spec.ts` (shipped un-skipped by the QA-20260902-03 repair PR, #201) seeds its marker `clients` row with `{ name: ... }`, but the `clients` table has no `name` column (the real column, used everywhere else in the codebase, is `display_name`). Its `beforeAll` throws on every run, failing the whole `[crew]` project and the `staging.yml` `e2e` job — on **every commit pushed to `staging` since PR #201 merged**, including the commit currently deployed to `https://staging.ops.marleymoves.co.uk`.

## Repro
1. On `staging`, run the e2e suite (or just the `[crew]` project) against any deployment from PR #201 (`99d5287`) onward: `npx playwright test e2e/crew/job-completion-status-consistency.spec.ts --project=crew`.
2. Expected: the spec seeds a marker client/lead/appointment and runs its one assertion.
3. Actual: `beforeAll` throws `Seeding marker client failed: Could not find the 'name' column of 'clients' in the schema cache` at `e2e/crew/job-completion-status-consistency.spec.ts:40`, failing the whole file.

## Suspected cause
`e2e/crew/job-completion-status-consistency.spec.ts:37` — `name:` should be `display_name:`, matching `clients`' actual schema and every other seed helper (`scripts/seed-e2e.mjs:252,753`, `e2e/fixtures/seed-data.ts`).
