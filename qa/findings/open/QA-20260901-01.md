## Summary
The public storage-agreement signing page (`/s/<token>`) shows a hardcoded sentence, "Invoices are payable by bank transfer on receipt.", right next to its link to the current storage terms — but that sentence now contradicts the terms it links to. `storage-terms` was bumped to v2 (`storage-terms-v2-2026-08-31`, effective 2026-08-31) specifically to clarify that storage charges can also be paid by card or cash, with no card surcharge. The page's own static copy still implies bank-transfer-only.

## Repro
1. No login needed. Seed (or use) any unsigned `storage_lets` row with a `sign_token`.
2. Visit `https://staging.ops.marleymoves.co.uk/s/<token>`.
3. Expected: the payment-method sentence on the page matches (or at least doesn't contradict) the storage-terms version the page links to.
4. Actual: the page renders the fixed string "Invoices are payable by bank transfer on receipt." regardless of which terms version is current.

## Evidence
`app/s/[token]/page.tsx:170`:
```tsx
              . Invoices are payable by bank transfer on receipt.
```
This sentence is hardcoded and unconditional (verified independently by reading the file — no branching, no lookup against `legal/manifest.json` or `lib/legal/documents.ts`).

`legal/storage-terms/v2-2026-08-31.md` (the CURRENT version this same page links to via `publicUrlFor("storage-terms")`) says, per its manifest summary and section 3 body: "Storage charges can be paid by bank transfer, card or cash. Bank transfer is preferred. We do not add a card fee."

Live confirmation this run: signed a fresh marker storage let through this exact page — the resulting `signatures` row correctly recorded `terms_version = 'storage-terms-v2-2026-08-31'`, `terms_sha256` matching the v2 hash in `legal/manifest.json`, and a `terms_snapshot` containing the v2 payment-method clause verbatim. So the SIGNATURE write path is fully correct and up to date — only the static page copy above the sign form is stale. This is a pure display-copy bug, not a write-path or data-integrity issue.

## Suspected cause
`app/s/[token]/page.tsx:170` — a hardcoded sentence written before the v1→v2 storage-terms update (which added card/cash as accepted payment methods with no surcharge) and never updated alongside it. The repair agent should verify independently, but the safest fix is to source this sentence from the current storage-terms version's own summary/body (or a small shared constant kept in lockstep with `legal/manifest.json`) rather than a second hand-maintained copy of the same fact — the customer-terms v3 bump introduced exactly this kind of "clarify all three payment methods are accepted" phrasing already reused correctly elsewhere (`/q/[token]` renders the equivalent copy without contradiction).

## Verify
On `/s/<token>` for any storage let (signed or not), the payment-method sentence on the page must not contradict the storage-terms version currently in effect — specifically, once v2 is current, it must not claim bank-transfer-only. A permanent assertion should check the visible page text against `currentVersion("storage-terms")`'s payment-method language (or simply assert the sentence mentions card and cash, not just bank transfer) rather than hardcoding today's exact wording.
