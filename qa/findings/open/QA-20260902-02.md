## Summary
A crew member who logs ONLY an expense for a day (no start/finish times) sees that day's hours cell still say the red "Add" label right next to the expense chip that proves the day was touched, and the week header simultaneously reads "Nothing logged yet · £4.20 expenses" — two parts of the same screen disagreeing about whether the day has anything logged.

## Repro
1. Log in as crew (marker user, e.g. a fresh `staff`-linked profile with `staff_role: "crew"`).
2. Go to `/my-jobs/hours`, tap an empty day tile.
3. Enter an expense amount (e.g. `4.20`) and a note, upload a receipt photo, leave start/finish time empty, Save.
4. Expected: the day's hours cell reflects that the day has real content (something other than the bare red "Add" prompt used for genuinely untouched days), and the week summary line doesn't say "Nothing logged yet" for a week that has an expense total on the very same line.
5. Actual: the hours cell still shows red "Add" (identical to a completely empty day) even though the expense chip (`£4.20` + receipt icon) renders right next to it, and the week header shows `"Nothing logged yet · £4.20 expenses"`.

## Evidence
`components/my-jobs/hours-editor.tsx`:
- Lines ~171–180: the hours-column label falls through to `"Add"` whenever `hours == null` and neither `entry?.started_at` nor `entry?.ended_at` is set — it does not check `entry?.expense_amount`/receipt fields, so an expense-only row (hours null, no start/end) renders identically to a genuinely empty day:
  ```tsx
  {hours != null ? (
    ...
  ) : entry?.started_at || entry?.ended_at ? (
    <span className="block text-xs font-medium text-warn">Unfinished</span>
  ) : future ? (
    <span className="block text-xs text-mist-400">—</span>
  ) : (
    <span className="block text-xs font-medium text-mm-red">{week.lockedRef ? "—" : "Add"}</span>
  )}
  ```
- Lines ~117–125: the week-summary line computes `totalHours` from `entryHours(started_at, ended_at)` only, and independently computes `totalExpenses` from `expense_amount` — then renders `totalHours > 0 ? "X hrs" : "Nothing logged yet"` concatenated with `totalExpenses > 0 ? " · £Y expenses" : ""`, so an expense-only week produces the literal self-contradictory string `"Nothing logged yet · £4.20 expenses"`:
  ```tsx
  {totalHours > 0 ? `${+totalHours.toFixed(2)} hrs` : "Nothing logged yet"}
  {totalExpenses > 0 ? ` · ${gbp(totalExpenses)} expenses` : ""}
  ```
- Confirmed live against a real marker row this run: `staff_time_entries` row existed with `expense_amount: 4.2`, `receipt_key` set, `receipt_emailed_at` stamped (the row is genuinely "logged" — the office-facing pipeline already treats it as real, receipted, emailed data) while the UI's own "needs attention" signal (the red "Add" text) said the day was untouched, and the week header simultaneously claimed nothing was logged. Screenshot: `qa-crew-42-after-save.png` (run artifact, not committed — describe only).

## Suspected cause
`components/my-jobs/hours-editor.tsx`:
- The hours-cell label branch (~line 171–180) should also treat "has an expense" as non-empty, not just "has start/end time" — e.g. checking `entry?.expense_amount` alongside `started_at`/`ended_at` before falling through to `"Add"`.
- The week-summary line (~line 117–125) should not print "Nothing logged yet" when `totalExpenses > 0` — the two clauses need to share one "is this week empty" condition instead of `totalHours` and `totalExpenses` being tested independently.

## Verify
Seed a `staff_time_entries` row with `expense_amount` set and `started_at`/`ended_at` both null (no hours). On `/my-jobs/hours`:
1. The day's cell must not show the same "Add" prompt used for a genuinely empty day (it must visibly reflect that the day has content, e.g. keep the "Unfinished"-style treatment or a distinct label).
2. The week-summary line must not read "Nothing logged yet" for a week whose `totalExpenses > 0`.

## Fix

`components/my-jobs/hours-editor.tsx`, both halves of the disagreement:

- **Day cell**: added an expense-only branch to the label ladder, between "Unfinished" and the
  future/"Add" fallbacks — `entry?.expense_amount != null || entry?.has_receipt` renders a neutral
  "Expense only" (mist, not the red needs-attention treatment). The receipt half of the check
  matters because the actions layer deliberately allows a receipt to land before an amount is
  typed (`upsertMyTimeEntryAction` docstring), so a row can hold `has_receipt` with
  `expense_amount` null. Genuinely empty days still show "Add"; days with any start/finish time
  are untouched ("Unfinished"/hours win first, as before).
- **Week summary**: the line is now built from a `summaryParts` array (hours part, expenses part)
  with ONE emptiness verdict — "Nothing logged yet" renders only when both parts are absent, so
  the self-contradictory "Nothing logged yet · £4.20 expenses" string is impossible.

Safe because it is pure client-side presentation in one component — no server action, schema,
payments or comms code is touched, and no existing e2e assertion changes meaning (`e2e/` grepped:
`crew/hours.spec.ts` asserts "Add" only on days with no entry, which still holds; the
expense-receipt spec fills hours alongside the expense, so its tile shows hours).

Test: `tests/components/hours-editor-expense-only.test.ts` (source-guard style per the
tests/components convention) — 5 assertions locking the ladder order, the neutral label, the
two-part condition, the shared summary verdict, and the absence of the old independent
concatenation. Proven RED against the pre-fix source (all 5 fail) and green after.
