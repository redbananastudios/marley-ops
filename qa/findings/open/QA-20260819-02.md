## Summary
`scripts/seed-e2e.mjs`'s cubic-survey seed writes `cubic_surveys.items` in a shape the app's own `CubicLine` type rejects, so any customer opening a survey seeded this way can never submit — silently, with no ops alert or log.

## Repro
1. Seed a `cubic_surveys` row with `items: [{ key: "sofa_2", label: "2-seat sofa", qty: 1, ft3: 35 }]` (the exact literal `scripts/seed-e2e.mjs`'s `SEED.cubicSurvey` block writes) and a `share_token`.
2. As a customer (no login), open `/cv/<that token>`, add an item, and submit.
3. The submit returns "This survey needs attention — call us on 01747 637070." every time. `cubic_surveys.status` stays `draft`, `updated_at` unchanged, `total_ft3` stays `0`.
4. Reseed the same row with a spec-correct `CubicLine` shape (`{ id, key, title, category, qty, unitFt3 }`) and repeat — submit succeeds cleanly, `status` → `customer_submitted`, `items` array grows, `total_ft3` recalculates correctly.

## Evidence
- `lib/cubic-survey.ts:21-31` — `CubicLine` requires `id: string; key: string; title: string; category: string; qty: number; unitFt3: number`.
- `scripts/seed-e2e.mjs` (`SEED.cubicSurvey` block, ~line 74, and the insert at ~line 538) — seeds `items: [{ key: "sofa_2", label: "2-seat sofa", qty: 1, ft3: 35 }]`: missing `id`/`title`/`category`/`unitFt3`, using `label`/`ft3` instead of `title`/`unitFt3`.
- `app/cv/[token]/actions.ts` (`submitCubicCustomerAction`) calls `sanitizeCubicLines()` on the stored row before allowing a submit; on the seeded shape it returns `null`/fails validation, which the action turns into the generic "needs attention" message with no distinguishing log or alert.
- Reproduced live on staging 2026-08-19: seeded row with the buggy shape → submit attempt left `status='draft'`, `total_ft3=0`; reseeded row with a corrected `CubicLine` shape → submit succeeded, `status='customer_submitted'`, `total_ft3` correctly recalculated (37 = 35 existing + 2 added).

## Suspected cause
`scripts/seed-e2e.mjs` line ~74 (`SEED.cubicSurvey`) and its insert around line ~538 use a stale/simplified item shape that predates (or never matched) `CubicLine` in `lib/cubic-survey.ts`.

Real-world customer risk is low — production surveys are always written by the office's `CubicBuilder`, which already produces spec-compliant `CubicLine[]`, so a real customer is very unlikely to hit this. It IS a live trap for the test suite: any spec that seeds via this script and later exercises the customer *submit* path (not just render) will hit the same wall. Separately worth considering (not required for this fix): `sanitizeCubicLines()` failing on a row that was already stored (as opposed to bad client input) is currently indistinguishable from bad client input to the office — no log/alert fires either way.

## Verify
1. Confirm `scripts/seed-e2e.mjs`'s `SEED.cubicSurvey` items literal (and its insert) now produces objects passing `sanitizeCubicLines()` — i.e. each item carries `id`, `key`, `title`, `category`, `qty`, `unitFt3`.
2. Re-run the repro: seed via the corrected script, open `/cv/<token>`, add an item, submit — must succeed (`status` → `customer_submitted`, no "needs attention" message).
