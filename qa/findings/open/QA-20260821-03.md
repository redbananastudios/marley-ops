## Summary
On the crew job-detail page, when an appointment's lead has no accepted quote, the "Vehicles" card renders the *packing*-label fallback text "See quote" as its subtitle — which reads as an instruction about vehicles, not packing.

## Repro
1. Crew login → open `/my-jobs/<id>` for a removal appointment whose lead has no `quotes` row with `status='accepted'`.
2. Look at the "Vehicles" card.
3. Expected: either nothing renders under "Vehicles" when there's no vehicle info, or any packing-related fallback text is scoped to a packing-labelled area, not the Vehicles card.
4. Actual: the card renders "VEHICLES" (heading) → "See quote" (subtitle) → "No vehicles assigned yet…". "See quote" is `packingLabel`'s no-quote fallback, not vehicle info.

Concretely on staging (2026-08-21), a QA-SENTINEL marker removal appointment with no accepted quote rendered the job-detail page text exactly:
`"VEHICLES / See quote / No vehicles assigned yet — the office will assign them…"`.

This isn't only a seeded-marker edge case: per the current changelog, iMVE-imported/legacy bookings can legitimately have no accepted quote at all, so this fallback is reachable on real jobs.

## Evidence
Source, read 2026-08-21:
- `lib/job-sheet-data.ts:100-101` —
  ```ts
  vehicleLabel: q ? vehicleLabelOf(q) : "",
  packingLabel: q ? (PACK_LABELS[q.packing] ?? q.packing) : "See quote",
  ```
  When there's no accepted quote (`q` is null/undefined), `vehicleLabel` is `""` (correctly renders nothing) but `packingLabel` falls back to the string `"See quote"` — a packing-specific fallback with no quote-independent home in the UI.
- `app/my-jobs/[id]/page.tsx:244-246` — the "Vehicles" card renders `d.vehicleLabel` then, directly under it, `d.packingLabel`:
  ```tsx
  {eyebrow(<Truck className="size-3.5" strokeWidth={1.75} />, "Vehicles")}
  {d.vehicleLabel ? <p className="mt-1.5 text-sm font-medium text-foreground">{d.vehicleLabel}</p> : null}
  {d.packingLabel ? <p className="text-xs text-mist-400">{d.packingLabel}</p> : null}
  ```
  There is no `d.vehicleLabel` set, so the `d.packingLabel` line ("See quote") appears alone as the Vehicles card's subtitle.

## Suspected cause
Two-hats-adjacent: `packingLabel`'s no-quote fallback text ("See quote") was written assuming it always renders in a packing-labelled context, but it's reused as the Vehicles card's subtitle whenever `vehicleLabel` is empty, with nothing to disambiguate which field it's talking about.

## Verify
On `/my-jobs/<id>` for an appointment whose lead has no accepted quote, assert the Vehicles card either shows nothing (no subtitle) or does not display packing-fallback text ("See quote") as if it described vehicles.
